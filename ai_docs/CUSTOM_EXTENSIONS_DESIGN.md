# Custom Extensions System Design

## Overview

The custom extensions system enables users to extend meroku-managed infrastructure with their own Terraform code while maintaining bidirectional integration with core modules.

## Architecture

```
project-folder/
├── dev.yaml                    # Environment config with extensions
├── prod.yaml
├── custom/                     # User's custom code (version controlled)
│   ├── pre/                    # Runs BEFORE core modules
│   │   ├── main.tf             # Custom module that outputs values for core
│   │   ├── variables.tf
│   │   └── outputs.tf          # Feeds into workloads module
│   ├── post/                   # Runs AFTER core modules
│   │   ├── main.tf             # Consumes core module outputs
│   │   ├── variables.tf
│   │   └── outputs.tf
│   └── terraform/              # Raw .tf files (appended to main.tf)
│       ├── _shared/            # All environments
│       └── dev/                # Environment-specific
└── env/
    └── dev/
        ├── main.tf             # Generated with custom modules included
        └── _bridge.tf          # Generated - exposes all outputs
```

## Integration Types

### 1. One-Way: Custom → Core Outputs (Post-Module)

Custom code consumes core module outputs.

**Use Case**: SNS webhook subscription that needs API Gateway endpoint

```hcl
# custom/post/main.tf
resource "aws_sns_topic_subscription" "webhook" {
  topic_arn = var.sns_topic_arn
  protocol  = "https"
  endpoint  = "${var.api_endpoint}/webhooks/sns/bounce"
}
```

### 2. One-Way: Core → Custom Outputs (Pre-Module)

Custom code creates resources that core modules reference.

**Use Case**: Create SNS topic, pass ARN to backend env vars

```hcl
# custom/pre/main.tf
resource "aws_sns_topic" "sms" {
  name = "${var.project}-${var.env}-sms-delivery"
}

# custom/pre/outputs.tf
output "backend_env_vars" {
  value = [
    { name = "AWS_SNS_SMS_TOPIC_ARN", value = aws_sns_topic.sms.arn }
  ]
}
```

### 3. Bidirectional: YAML Extensions

Common patterns defined in YAML with automatic wiring.

**Use Case**: SNS topic with webhook subscription AND backend env var

```yaml
# dev.yaml
extensions:
  sns_topics:
    - name: sms_delivery
      add_to_backend_env: AWS_SNS_SMS_TOPIC_ARN
      webhooks:
        - path: /webhooks/sns/sms
          raw_message_delivery: true
```

## Generated Terraform Structure

```hcl
# ============================================================================
# GENERATED BY MEROKU - DO NOT EDIT MANUALLY
# ============================================================================

terraform { ... }

# Core data sources
data "aws_caller_identity" "current" {}
data "aws_region" "current" {}

# VPC configuration
module "vpc" { ... }
locals {
  vpc_id     = module.vpc.vpc_id
  subnet_ids = module.vpc.subnet_ids
}

# ============================================================================
# CUSTOM PRE-MODULE (runs before core modules)
# ============================================================================
module "custom_pre" {
  count  = fileexists("../../custom/pre/main.tf") ? 1 : 0
  source = "../../custom/pre"

  # Context passed to custom module
  project    = "myproject"
  env        = "dev"
  region     = "ap-southeast-2"
  account_id = data.aws_caller_identity.current.account_id
  vpc_id     = local.vpc_id
  subnet_ids = local.subnet_ids
}

# ============================================================================
# YAML EXTENSIONS - SNS Topics
# ============================================================================
resource "aws_sns_topic" "ext_sms_delivery" {
  name = "myproject-dev-sms-delivery"
  tags = { ... }
}

# ============================================================================
# CORE MODULES
# ============================================================================
module "workloads" {
  source = "../../infrastructure/modules/workloads"

  # Backend env vars merged from:
  # 1. YAML config
  # 2. Custom pre-module outputs
  # 3. YAML extensions
  backend_env = concat(
    [
      # From YAML backend_env_variables
      { name = "DATABASE_URL", value = "..." },
    ],
    # From custom pre-module (if exists)
    try(module.custom_pre[0].backend_env_vars, []),
    # From YAML extensions
    [
      { name = "AWS_SNS_SMS_TOPIC_ARN", value = aws_sns_topic.ext_sms_delivery.arn },
    ]
  )

  # ... rest of workloads config
}

# ============================================================================
# YAML EXTENSIONS - SNS Webhooks (after workloads for endpoint)
# ============================================================================
resource "aws_sns_topic_subscription" "ext_sms_delivery_webhook_0" {
  topic_arn              = aws_sns_topic.ext_sms_delivery.arn
  protocol               = "https"
  endpoint               = "${module.workloads.api_gateway_endpoint}/webhooks/sns/sms"
  endpoint_auto_confirms = true
  raw_message_delivery   = true
}

# ============================================================================
# CUSTOM POST-MODULE (runs after core modules)
# ============================================================================
module "custom_post" {
  count  = fileexists("../../custom/post/main.tf") ? 1 : 0
  source = "../../custom/post"

  # All context + core module outputs
  project      = "myproject"
  env          = "dev"
  region       = "ap-southeast-2"
  account_id   = data.aws_caller_identity.current.account_id
  vpc_id       = local.vpc_id
  subnet_ids   = local.subnet_ids

  # Core module outputs
  api_endpoint         = module.workloads.api_gateway_endpoint
  api_gateway_id       = module.workloads.api_gateway_id
  ecs_cluster_arn      = module.workloads.ecr_cluster.arn
  backend_ecr_repo_url = module.workloads.backend_ecr_repo_url
  backend_task_role    = module.workloads.backend_task_role_name

  # Domain outputs (if enabled)
  domain_zone_id       = module.domain.zone_id
  api_domain           = module.domain.api_domain_name

  # Database outputs (if enabled)
  db_endpoint          = module.postgres.endpoint
}

# ============================================================================
# RAW CUSTOM TERRAFORM (appended from custom/terraform/)
# ============================================================================
# Contents of custom/terraform/_shared/*.tf and custom/terraform/dev/*.tf
# are appended here

# ============================================================================
# BRIDGE OUTPUTS (for reference in custom code)
# ============================================================================
output "bridge" {
  description = "All values available for custom terraform"
  value = {
    project           = "myproject"
    env               = "dev"
    region            = data.aws_region.current.name
    account_id        = data.aws_caller_identity.current.account_id
    vpc_id            = local.vpc_id
    subnet_ids        = local.subnet_ids
    api_endpoint      = module.workloads.api_gateway_endpoint
    api_gateway_id    = module.workloads.api_gateway_id
    ecs_cluster_arn   = module.workloads.ecr_cluster.arn
    backend_task_role = module.workloads.backend_task_role_name
  }
  sensitive = false
}
```

## YAML Extensions Schema

### SNS Topics

```yaml
extensions:
  sns_topics:
    - name: string              # Required: Topic name suffix
      display_name: string      # Optional: Human-readable name
      add_to_backend_env: string # Optional: Env var name for ARN
      fifo: bool                # Optional: FIFO topic (default: false)
      content_based_dedup: bool # Optional: For FIFO (default: false)
      kms_key_id: string        # Optional: KMS encryption
      webhooks:                 # Optional: HTTP/S subscriptions
        - path: string          # Required: Backend endpoint path
          raw_message_delivery: bool  # Optional (default: false)
          filter_policy: object # Optional: SNS filter policy
```

### SQS Queues

```yaml
extensions:
  sqs_queues:
    - name: string              # Required: Queue name suffix
      add_to_backend_env: string # Optional: Env var name for URL
      fifo: bool                # Optional: FIFO queue
      visibility_timeout: int   # Optional: seconds (default: 30)
      message_retention: int    # Optional: seconds (default: 345600)
      dlq_enabled: bool         # Optional: Create DLQ (default: true)
      dlq_max_receive: int      # Optional: Before DLQ (default: 3)
      sns_subscription: string  # Optional: SNS topic to subscribe to
```

### S3 Event Notifications

```yaml
extensions:
  s3_notifications:
    - bucket: string            # Required: Bucket name from buckets[]
      events:                   # Required: Event configurations
        - type: sns|sqs|lambda  # Required: Destination type
          target: string        # Required: Target name (from extensions)
          events:               # Required: S3 events
            - s3:ObjectCreated:*
          prefix: string        # Optional: Key prefix filter
          suffix: string        # Optional: Key suffix filter
```

### Lambda Functions

```yaml
extensions:
  lambda_functions:
    - name: string              # Required: Function name
      runtime: string           # Required: nodejs20.x, python3.12, go1.x
      handler: string           # Required: Handler path
      source_dir: string        # Required: Path relative to project root
      memory: int               # Optional: MB (default: 128)
      timeout: int              # Optional: seconds (default: 30)
      add_to_backend_env: string # Optional: Env var for function ARN
      environment: object       # Optional: Lambda env vars
      triggers:                 # Optional: Event triggers
        - type: sns|sqs|s3|schedule|api_gateway
          source: string        # Reference to extension or config
```

### EventBridge Rules

```yaml
extensions:
  eventbridge_rules:
    - name: string              # Required: Rule name
      schedule: string          # Optional: rate() or cron()
      event_pattern: object     # Optional: Event pattern
      targets:
        - type: lambda|ecs|sqs|sns
          target: string        # Reference to extension
```

## Implementation Phases

### Phase 1: Custom Terraform Directory
- Append raw .tf files from `custom/terraform/`
- No bidirectional integration
- Simple file concatenation

### Phase 2: Bridge File Generation
- Generate `_bridge.tf` with all outputs as locals
- Custom code can reference `local.bridge.*`

### Phase 3: Custom Pre/Post Modules
- Support `custom/pre/` and `custom/post/` directories
- Pass context variables and receive outputs
- Enable bidirectional integration

### Phase 4: YAML Extensions
- SNS topics with webhooks
- SQS queues with subscriptions
- Lambda functions
- EventBridge rules
- S3 notifications

## File Detection Logic

```go
func hasCustomPre() bool {
    return fileExists("custom/pre/main.tf")
}

func hasCustomPost() bool {
    return fileExists("custom/post/main.tf")
}

func getCustomTerraformFiles(env string) []string {
    files := []string{}
    // Shared files
    files = append(files, glob("custom/terraform/_shared/*.tf")...)
    // Environment-specific
    files = append(files, glob("custom/terraform/"+env+"/*.tf")...)
    return files
}
```

## Migration Notes

- Existing `custom/appsync/` directory remains supported
- New `custom/` subdirectories are opt-in
- No changes required for existing projects
